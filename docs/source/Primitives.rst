
Primitives
==========

This section provides a brief overview of the primitives used
by the SCALES Data Reduction Pipeline (SCALES-DRP).

The primary data products generated by both the IFS and imaging
channels include:

* A ramp-fitted slope image.
* The corresponding uncertainty map.
* Associated data quality (DQ) flags.
* A chi-square map from the ramp fitting.

In addition to these products, the IFS channel generates:

* A three-dimensional data cube with two spatial dimensions
  and one spectral dimension.
* The corresponding uncertainty cube.

The following sections describe the individual primitives
in their order of execution.

All primitive implementations are located in the
``scalesdrp/primitives/`` directory of the SCALES-DRP repository:

.. code-block:: text

   SCALES-DRP/
   └── scalesdrp/
       └── primitives/



.. _referencepixel:

Reference Pixel Correction
--------------------------

**Corrects amplifier-dependent baseline offsets using the top and
bottom detector reference pixels.**

The SCALES detectors have four amplifier outputs, each covering
512 columns of the 2048 x 2048 detector. Differences in the
electronic offsets between amplifiers can introduce discontinuities
in the detector images.

This primitive estimates and subtracts these offsets using the
non-illuminated reference pixels located along the top and bottom
edges of the detector. By default, the top and bottom four reference
rows are used to estimate the amplifier offsets independently for
each detector read.

The DRP supports three reference pixel correction methods:

.. list-table:: Available amplifier reference pixel correction methods
   :header-rows: 1
   :widths: 28 72

   * - Method
     - Description
   * - Odd/even amplifier correction
     - Estimates separate scalar offsets for odd and even columns
       within each amplifier for every detector read.
   * - Amplifier-wise correction
     - Estimates a single scalar offset for each amplifier
       independently for every detector read.
   * - Column-wise correction
     - Estimates an individual offset for each detector column
       using the corresponding top and bottom reference pixels.

The correction is applied to the entire detector frame, including
the science region and reference pixels.

**Implementation:** ``reffix_amps()`` in
``scalesdrp/primitives/reference.py``.

.. figure:: /_static/plots/read_refpix.png
   :width: 600px
   :align: center

   Example of reference pixel correction applied to an imaging
   detector read. The panels show the raw image (left), the
   estimated amplifier offsets for odd and even columns (middle),
   and the corrected image (right).


.. _acncorrection:

Alternating Column Noise (ACN) Correction
-----------------------------------------

**Corrects row-dependent differences between odd and even detector
columns using the side reference pixels.**

In addition to amplifier-level baseline offsets, the detector
can exhibit alternating column noise (ACN), which produces
differences between odd and even columns that vary along the
detector rows.

Unlike the amplifier reference pixel correction, which estimates
a constant offset for each amplifier and read, this primitive
estimates separate row-dependent noise profiles for odd and
even columns.

The correction uses the left and right reference-pixel columns.
The reference pixels are separated into odd and even groups,
and their baseline levels are removed before constructing
a one-dimensional noise profile for each group.

The DRP supports three methods for removing the reference-pixel
baseline:

.. list-table:: Available ACN baseline removal methods
   :header-rows: 1
   :widths: 25 75

   * - Method
     - Description
   * - Per-pixel
     - Removes the temporal average of each reference pixel
       over the integration before estimating the row-dependent
       noise profile.
   * - Per-frame
     - Removes a single average reference level independently
       for each detector read.
   * - Per-integration
     - Removes a single average reference level over the
       complete integration.

The resulting odd and even row profiles can optionally be
smoothed using FFT-based optimal filtering or Savitzky-Golay
filtering. The correction can be performed independently
for each read or smoothed across the integration.

The estimated profiles are subtracted separately from the
corresponding odd and even columns across the entire detector
frame.

**Implementation:** ``acn_filter()`` in
``scalesdrp/primitives/reference.py``.


.. _onebyf:

1/f Noise Correction
--------------------

**Estimates and subtracts row-dependent correlated noise using
the left and right detector reference pixels.**

The SCALES detectors exhibit low-frequency correlated noise,
commonly referred to as 1/f noise, which can introduce horizontal
striping in detector images.

This primitive uses the non-illuminated reference-pixel columns
along the left and right edges of the detector to estimate the
correlated noise. For each detector read, the reference values
are combined into a one-dimensional profile describing the
noise as a function of detector row.

The DRP provides several approaches for constructing the
reference profile:

.. list-table:: Available reference profile estimation methods
   :header-rows: 1
   :widths: 25 75

   * - Method
     - Description
   * - Row-wise
     - Calculates the median reference value for each detector
       row and read, then removes the overall median of the
       row profile while preserving row-dependent variations.
   * - Per-pixel
     - Removes the temporal average of each reference pixel
       over the integration before estimating the noise profile.
   * - Per-frame
     - Removes a single reference baseline independently
       for each detector read.
   * - Per-integration
     - Removes a single reference baseline over the
       complete integration.

Once the reference profile is constructed, the DRP supports
two correction approaches:

.. list-table:: Available 1/f noise correction approaches
   :header-rows: 1
   :widths: 25 75

   * - Method
     - Description
   * - Direct subtraction
     - Subtracts the estimated row-dependent reference profile
       from the detector image. The profile can optionally be
       smoothed and scaled independently for each amplifier.
   * - Transfer-function correction
     - Uses a calibrated frequency-dependent transfer function
       to estimate the correlated noise in the science pixels
       from the reference-pixel signal. The correction is
       performed in Fourier space and can be applied separately
       to each amplifier.

For direct subtraction, the reference profile can be smoothed
using FFT-based optimal filtering or Savitzky-Golay filtering.
The FFT-based algorithm estimates the low-frequency correlated
signal while suppressing high-frequency white noise.

The FFT smoothing algorithm follows the approach of Kosarev
and Pantos. The original reference-pixel correction implementation
was developed by M. Robberto in
`IDL <http://www.stsci.edu/~robberto/Main/Software/IDL4pipeline/>`_,
while portions of the Python implementation are adapted from
`Jarron Leisenring
<https://github.com/JarronL/hxrg_ref_pixels/tree/main>`_.

The current DRP workflow uses direct reference-profile subtraction
with optional smoothing and amplifier-dependent scaling.
The transfer-function approach is available in the underlying
primitive for alternative correction strategies.

**Implementation:** ``ref_filter()`` and ``calc_col_smooth()``
in ``scalesdrp/primitives/reference.py``.

.. figure:: /_static/plots/onef_filter_img.png
   :width: 600px
   :align: center

   Frequency-domain representation of the FFT-based optimal
   smoothing filter applied to the side reference-pixel signal
   of an imaging detector flat-field read. The blue curve shows
   the reference signal power spectrum, the red dashed line
   indicates the estimated white-noise floor, and the green
   dotted curve represents the optimal filter transfer function.
   The filtered reference profile is transformed back into the

.. _residualcolumn:

Residual Column Correction
--------------------------

**Corrects residual column-dependent offsets using the top and
bottom detector reference pixels.**

After the amplifier reference pixel correction, residual
column-dependent offsets may remain in the detector images.
These offsets can produce vertical patterns that are not
completely removed by the amplifier-level correction.

This primitive estimates the residual offsets using the
non-illuminated reference pixels located along the top
and bottom edges of the detector.

For each detector read, the reference pixels are averaged
along the vertical direction to obtain an independent
offset for every detector column. The resulting
one-dimensional correction profile is then subtracted
from each row of the detector image.

Unlike the amplifier-wise reference pixel correction,
which removes a common offset from each amplifier,
this method estimates and removes an individual
offset for every detector column.

The correction is applied to the entire detector frame,
including the science region and reference pixels.

This correction is optional and can be enabled when
residual column-dependent patterns remain after the
initial amplifier reference pixel correction.

**Implementation:** ``sub_resid_col()`` in
``scalesdrp/primitives/reference.py``.


.. _rowpickup:

Evolving Row-Pickup Noise Correction
------------------------------------

**Estimates and removes evolving horizontal noise patterns
using consecutive detector-read differences.**

In addition to the correlated noise estimated from the
side reference pixels, the detector can exhibit residual
horizontal pickup patterns that vary between successive
reads.

These patterns may not be completely removed by the
standard reference pixel and 1/f noise corrections.

This primitive estimates the residual row-dependent
noise directly from the science pixels using differences
between consecutive detector reads.

For an input ramp containing multiple reads, the
difference between consecutive reads is calculated as:

.. math::

   D_i(x,y) = R_{i+1}(x,y) - R_i(x,y),

where :math:`R_i` represents the detector signal in
read :math:`i`, and :math:`D_i` is the corresponding
read-difference image.

For each difference image, a robust row-dependent
noise profile is estimated after masking bright sources,
outliers, and potentially contaminated pixels.

The source and outlier masks can be expanded using
binary dilation to exclude neighboring pixels,
including the wings of bright sources.

Rows containing insufficient valid pixels are estimated
by interpolation from neighboring rows.

The resulting row profile is used to construct a model
of the evolving horizontal pickup noise.

**Available correction approaches**

The DRP supports different approaches for estimating
and removing the row-dependent pickup pattern:

.. list-table:: Available row-pickup correction approaches
   :header-rows: 1
   :widths: 30 70

   * - Method
     - Description
   * - Full row-pattern correction
     - Estimates and removes the row-dependent pickup
       pattern from each consecutive-read difference.
       This approach can remove both persistent and
       time-variable stripe patterns.
   * - Variable row-pattern correction
     - Removes the median row profile across the
       read differences before estimating the
       correction. This approach targets the
       time-variable component of the pickup noise
       while preserving the common row pattern.

**Spatial filtering**

The estimated row profiles can be high-pass filtered
to isolate the stripe-scale noise from broader
spatial variations.

The high-pass correction is constructed by subtracting
a median-filtered version of the row profile:

.. math::

   P_{\mathrm{corr}}(y)
   =
   P(y) -
   \mathrm{MedianFilter}[P(y)],

where :math:`P(y)` is the estimated row-dependent
noise profile.

The median-filter window controls the spatial scale
of the correction. A smaller window removes
shorter-scale variations, while a larger window
preserves more of the slowly varying structure
in the estimated pickup profile.

The DRP also supports subtraction of the complete
row profile without high-pass filtering.

**Amplifier-dependent correction**

The row-pickup noise can be estimated using either
the entire science region or individual amplifier
channels.

.. list-table:: Available row-pickup estimation modes
   :header-rows: 1
   :widths: 30 70

   * - Method
     - Description
   * - Full-detector estimation
     - Estimates a common row-dependent pickup
       profile using the science pixels across
       the detector.
   * - Per-amplifier estimation
     - Estimates independent row-dependent pickup
       profiles for each amplifier, allowing
       amplifier-specific noise patterns to
       be corrected.

The correction can also be applied iteratively
to reduce residual pickup noise.

Unlike the reference-pixel-based 1/f correction,
this method estimates the noise directly from
the science-pixel read differences, with masking
to minimize contamination from astronomical
sources and outliers.

The correction is optional and is intended for
detector data exhibiting residual horizontal
pickup patterns after the standard reference
pixel and 1/f noise corrections.

**Implementation:** ``correct_evolving_row_pickup()``
in ``scalesdrp/primitives/reference.py``.



.. _linearity:

Linearity Correction
--------------------

**Corrects the nonlinear detector response using precomputed
per-pixel polynomial coefficients.**

The response of the SCALES detectors can deviate from linearity
as the accumulated signal increases. This nonlinearity can affect
the measured signal in individual detector reads and introduce
systematic errors in the subsequent ramp fitting.

The SCALES-DRP applies a pixel-dependent polynomial correction
using a previously generated  :ref:`linearity calibration reference
file <createlinearity>`. The correction follows a
`Brandt-style <https://github.com/RomanSpaceTelescope/SOCReferenceFileCode>`_ polynomial model
and is applied independently to each detector pixel and read.

The correction is expressed as:

.. math::

   L(M) = \sum_{k=0}^{n} c_k M^k,

where :math:`M` is the pedestal-subtracted measured signal,
:math:`L(M)` is the corresponding linearized signal, and
:math:`c_k` are the per-pixel polynomial coefficients.

The calibration convention fixes the constant and linear
coefficients to :math:`c_0=0` and :math:`c_1=1`, while the
higher-order terms describe the nonlinear detector response.

Correction Procedure
^^^^^^^^^^^^^^^^^^^^

The linearity correction is performed independently for each
detector ramp using the following steps:

1. **Pedestal estimation:** A per-pixel pedestal is estimated
   from the median of the first two detector reads.

2. **Pedestal subtraction:** The estimated pedestal is
   subtracted from every read to obtain the measured signal
   relative to the initial detector level.

3. **Saturation threshold:** A usable signal range is
   determined from the per-pixel saturation level stored
   in the calibration reference file. The correction is
   restricted to signals below 95% of the pedestal-subtracted
   saturation range.

4. **Polynomial correction:** The per-pixel polynomial
   is evaluated for reads within the usable signal range.

5. **Pedestal restoration:** The original pedestal is
   added back to the corrected signal, preserving the
   absolute detector count scale.

6. **Invalid pixel handling:** Pixels with invalid
   coefficients, invalid saturation levels, non-finite
   pedestals, or bad-pixel flags are left unchanged.

7. **Saturated read handling:** Reads at or above the
   usable saturation threshold are excluded from the
   polynomial correction and handled according to the
   selected saturated-read behavior.

For a detector read :math:`R_i(x,y)`, the corrected
absolute signal is given by:

.. math::

   R_{i,\mathrm{corr}}(x,y)
   =
   P(x,y) +
   \sum_{k=0}^{n}
   c_k(x,y)
   [R_i(x,y)-P(x,y)]^k,

where :math:`P(x,y)` is the estimated per-pixel pedestal.
This expression is evaluated only for pixels and reads
that satisfy the correction validity conditions.

Saturation Handling
^^^^^^^^^^^^^^^^^^^

The calibration reference file provides a per-pixel
saturation level in absolute detector counts (DN).
The usable saturation threshold is calculated as:

.. math::

   S_{\mathrm{usable}}(x,y)
   =
   f_{\mathrm{sat}}
   [S(x,y)-P(x,y)],

where :math:`S(x,y)` is the reference saturation level,
:math:`P(x,y)` is the input-ramp pedestal, and
:math:`f_{\mathrm{sat}}` is the selected saturation fraction.

In the current DRP implementation,
:math:`f_{\mathrm{sat}}=0.95`.

Reads whose pedestal-subtracted signals reach or exceed
this threshold are not corrected by the polynomial.

The DRP supports three approaches for handling these
reads:

.. list-table:: Available saturated-read handling methods
   :header-rows: 1
   :widths: 25 75

   * - Method
     - Description
   * - ``raw``
     - Preserves the original measured DN values for
       reads at or above the usable saturation threshold.
   * - ``nan``
     - Replaces these reads with ``NaN`` for pixels
       eligible for linearity correction.
   * - ``flat_last_valid``
     - Replaces later saturated reads with the last
       valid corrected value, producing a constant
       signal after the usable range is exceeded.

The current SCALES-DRP workflow uses the ``raw`` method,
preserving the original values of saturated reads.
These reads can subsequently be identified and excluded
during saturation masking and ramp fitting.

Invalid Pixel Handling
^^^^^^^^^^^^^^^^^^^^^^

The correction is applied only to pixels with valid
polynomial coefficients, a finite pedestal, and a
valid saturation range.

The reference file contains the following products
used during correction:

.. list-table:: Linearity calibration products used by the correction
   :header-rows: 1
   :widths: 25 75

   * - Extension
     - Description
   * - ``COEFF``
     - Per-pixel polynomial coefficients stored in
       ascending order of polynomial power.
   * - ``SATURATION``
     - Per-pixel saturation level in absolute DN,
       used to determine the usable correction range.
   * - ``BPM``
     - Optional bad-pixel mask identifying pixels
       excluded from the polynomial correction.
   * - ``SUCCESS``
     - Optional calibration success map identifying
       pixels with successful coefficient fits.

Pixels with non-finite coefficients, invalid saturation
levels, non-finite pedestals, or bad-pixel flags are
left unchanged.

The correction also supports restricting polynomial
evaluation to pixels marked as successful in the
calibration reference file. In the current workflow,
this restriction is disabled, allowing all otherwise
valid coefficient vectors to be evaluated. Pixels
assigned identity coefficients during calibration
therefore retain their original measured values.

If polynomial evaluation produces non-finite results
for a pixel, the complete pixel ramp is left unchanged.

Outputs
^^^^^^^

The primitive returns a corrected detector ramp with
the same dimensions as the input.

When auxiliary outputs are requested, the routine
also returns:

* ``pedestal``: A two-dimensional image containing
  the estimated pedestal for each detector pixel.

* ``sat_mask``: A three-dimensional Boolean mask
  identifying reads outside the usable saturation
  range or otherwise invalid for correction.

* ``applied_mask``: A two-dimensional Boolean mask
  identifying pixels eligible for the polynomial
  correction.

The saturation and applied masks can also be used
for diagnostic plots to evaluate the correction
performance.

**Implementation:** ``apply_brandt_linearity_reference()``
in ``scalesdrp/primitives/linearity_correct.py``.

.. _ramp:

Ramp Fitting
------------

**Estimates the count rate of each detector pixel from nondestructive
ramp reads using generalized least-squares fitting.**

The SCALES DRP adopts the `Brandt fitramp algorithm
<https://github.com/t-brandt/fitramp>`_ to estimate detector count
rates from nondestructive reads. The algorithm uses generalized
least-squares (GLS) fitting to account for both read noise and
photon noise, including their covariance.

The fitting is performed using differences between consecutive
detector reads. The covariance model incorporates the noise
contributions and correlations between these differences,
allowing statistically efficient estimation of the count rate.

The DRP uses a per-pixel noise map (``SIG_map_scaled``) as input
to the ramp fitter. The fitting procedure also supports an
estimate of the detector pedestal and iterative identification
of discontinuities caused by cosmic-ray events.

Additional details of the algorithm are described in
`Brandt et al. (2024a)
<https://iopscience.iop.org/article/10.1088/1538-3873/ad38d9/pdf>`_
and
`Brandt et al. (2024b)
<https://iopscience.iop.org/article/10.1088/1538-3873/ad38da>`_.

Before ramp fitting, the pipeline constructs a dynamic read-validity
mask using saturation map from :ref:`linearity correction <linearity>`,
the input detector cube,
and the master bad-pixel map. This mask excludes reads affected
by saturation and propagates saturation masking to neighboring
detector pixels.

Behaviour
^^^^^^^^^

* Estimates the count rate independently for each detector pixel
  using valid nondestructive read differences.

* Uses the per-pixel noise estimate to construct the covariance
  model for GLS fitting.

* Identifies saturated reads using the saturation map
  and excludes the affected portion of each detector ramp.

* Applies nearest-neighbor saturation masking to account for
  possible contamination of pixels surrounding a saturated pixel.

* Rejects non-finite reads and excludes consecutive-read
  differences involving rejected reads.

* Detects jump events, including cosmic-ray hits, using
  the ``fitramp`` jump-detection algorithm.

* Performs the final GLS fit using the remaining valid
  read differences and an optional pedestal constraint.

* Falls back to ordinary least-squares (OLS) fitting when
  a valid GLS solution cannot be obtained.

* Returns the fitted count rate, pedestal, uncertainty,
  and chi-square statistic for each detector pixel.

Saturation and Nearest-Neighbor Masking
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

Before ramp fitting, the DRP generates a two-dimensional detector
quality map and a three-dimensional read-validity mask using
``make_ramp_quality_mask()``.

The routine compares each detector read against the corresponding
pixel's saturation threshold from the saturation map.

For each pixel, the first saturated read is identified as:

.. math::

  r_{\mathrm{sat}}(x,y)
  =
  \min\left\{
  r : D_r(x,y) \geq S(x,y)
  \right\},

where :math:`D_r(x,y)` is the detector signal in read :math:`r`
and :math:`S(x,y)` is the per-pixel saturation threshold in DN.

If a pixel never reaches its saturation threshold, no direct
saturation cutoff is assigned.

Once saturation is detected, the saturated read and all
subsequent reads are marked invalid for ramp fitting.

**Nearest-neighbor masking**

Saturation can also affect nearby detector pixels. To account
for this, the DRP extends the saturation mask to neighboring
pixels using a configurable spatial radius.

With ``neighbor_radius=1``, the masking includes the saturated
pixel and its eight nearest neighbors, corresponding to a
3 x 3 pixel region.

For each pixel, the effective cutoff is the earliest saturation
read among the pixels in this neighborhood:

.. math::

  r_{\mathrm{cut}}(x,y)
  =
  \min_{(u,v)\in\mathcal{N}(x,y)}
  r_{\mathrm{sat}}(u,v),

where :math:`\mathcal{N}(x,y)` represents the selected
neighborhood around pixel :math:`(x,y)`.

A neighboring pixel can therefore cause a ramp to be
truncated earlier than its own saturation threshold,
even when that pixel never directly saturates.

**Read-validity mask**

The final three-dimensional Boolean mask,
``good_read_mask``, has the same dimensions as the
input detector cube:

.. code-block:: text

  (Nreads, Height, Width)

Each element indicates whether a particular read is
available for ramp fitting:

* ``True``: The read is finite and occurs before
  the effective saturation cutoff.

* ``False``: The read is non-finite, saturated,
  affected by a saturated neighbor, or associated
  with an invalid saturation threshold.

The mask is constructed as:

.. math::

   G_r(x,y)
   =
   \left[r < r_{\mathrm{cut}}(x,y)\right]
   \land
   \mathrm{finite}\left(D_r(x,y)\right),

with all reads additionally rejected for pixels having
invalid saturation thresholds.

The master bad-pixel map is included in the detector
quality map but does not directly remove those pixels
from ramp fitting. Bad-pixel correction is performed
separately on the resulting slope image.

Detector Quality Flags
^^^^^^^^^^^^^^^^^^^^^^

The saturation-masking routine produces a two-dimensional
quality map, ``quality_map``, containing the following flags:

.. list-table:: Ramp-fitting detector quality flags
   :header-rows: 1
   :widths: 25 15 60

   * - Flag
     - Bit value
     - Description
   * - ``BPM``
     - 1
     - Pixel identified in the master bad-pixel map.
   * - ``SATURATED``
     - 2
     - Pixel directly reaches its saturation threshold.
   * - ``SAT_NEIGHBOR``
     - 4
     - A neighboring saturated pixel causes an earlier
       ramp cutoff.
   * - ``INVALID_SAT_MAP``
     - 8
     - Pixel has an invalid or unavailable saturation
       threshold.

Multiple flags can be assigned to the same detector pixel.

The ``quality_map`` records detector-level conditions,
while ``good_read_mask`` determines which reads are
available to the ramp-fitting algorithm.

Ramp-Fitting Procedure
^^^^^^^^^^^^^^^^^^^^^^

The ramp-fitting routine performs the following operations:

1. **Read validation:** The input detector cube is checked
   for non-finite values. Optional sigma clipping can
   additionally reject outlying reads.

2. **Dynamic masking:** The ``good_read_mask`` is combined
   with the finite-read mask. A consecutive-read difference
   is usable only when both contributing reads are valid.
   Pixels without at least one valid consecutive-read pair
   are excluded from fitting.

3. **Initial slope estimation:** An initial count-rate
   estimate is obtained using ``fitramp`` when sufficient
   valid differences are available. OLS is used when
   the initial GLS estimate cannot be obtained.

4. **Jump detection:** The algorithm examines the
   consecutive-read differences for discontinuities
   using the one-omit and two-omit jump-detection tests.
   Differences identified as jumps are excluded.

5. **Final GLS fitting:** The remaining valid differences
   are fitted using the covariance model, including
   a pedestal constraint when available. The fit
   estimates the count rate, pedestal, uncertainty,
   and chi-square statistic.

6. **Fallback fitting:** Pixels for which GLS fitting
   fails or cannot be performed are processed using
   an OLS fallback. The fallback uses only valid,
   uncontaminated reads and strictly preserves the
   saturation and jump-rejection masks.

7. **Failed-fit handling:** Pixels without sufficient
   valid data, or for which both fitting approaches
   fail, are assigned predefined sentinel values
   rather than being fitted using rejected reads.

Both GLS and OLS fitting require sufficient valid data
to estimate the detector count rate. The dynamic
read-validity mask is strictly enforced throughout
the fitting procedure. In particular, saturated reads
and reads rejected because of neighboring saturation
are never restored when the likelihood solution fails.

Pixels with no valid consecutive-read pair are marked
as failed fits. The corresponding slope and pedestal
are set to zero, the uncertainty is set to
``1e30``, and the chi-square is set to ``-1``.
These values prevent the propagation of non-finite
results while preserving an explicit indication of
unsuccessful ramp fitting.


Ramp-Fit Quality Assessment
^^^^^^^^^^^^^^^^^^^^^^^^^^^

Following ramp fitting and jump rejection, the SCALES DRP
evaluates the quality of the resulting slope image to determine
whether the exposure satisfies the configured quality criteria.

The assessment is performed using ``assess_ramp_fit_quality()``,
which takes the fitted slope, uncertainty, chi-square,
detector quality map (``quality_map``), and three-dimensional
read-validity mask (``good_read_mask``) as inputs.

The routine evaluates the fraction of successfully fitted pixels,
identifies failed fits, and examines the goodness-of-fit statistics
where sufficient degrees of freedom are available. The results
are recorded in the FITS header for subsequent quality screening.

**Identification of failed fits**

A ramp fit is considered unsuccessful when insufficient valid
consecutive reads remain after saturation masking and jump
rejection, or when neither the GLS nor OLS fitting procedure
produces a valid solution.

Failed fits are assigned the following sentinel values:

.. code-block:: text

   Slope       = 0.0
   Pedestal    = 0.0
   Uncertainty = 1e30
   Chi-square  = -1.0

These values prevent the propagation of non-finite results
while allowing failed pixels to be identified explicitly.

The assessment distinguishes pixels flagged in the master
bad-pixel map (BPM) from the remaining detector pixels.

By default, master-BPM pixels are excluded from the
exposure-level quality assessment because they are handled
separately during bad-pixel correction. Nevertheless, failed
fits among master-BPM pixels are counted independently.

The total number of failed fits is therefore

.. math::

   N_{\mathrm{failed,total}}
   =
   N_{\mathrm{failed,assessed}}
   +
   N_{\mathrm{failed,BPM}}.

**Valid-fit fraction**

The primary quality metric is the fraction of successfully
fitted pixels:

.. math::

   f_{\mathrm{valid}}
   =
   \frac{N_{\mathrm{valid}}}
   {N_{\mathrm{assessed}}},

where :math:`N_{\mathrm{assessed}}` is the number of detector
pixels included in the quality assessment, excluding
master-BPM pixels by default, and :math:`N_{\mathrm{valid}}`
is the number of those pixels with successful ramp fits.

The corresponding failed-fit fraction is

.. math::

   f_{\mathrm{failed}} = 1 - f_{\mathrm{valid}}.

The default minimum acceptable valid-fit fraction is 0.95,
corresponding to at least 95% successful ramp fits among
the assessed detector pixels.

This threshold is configurable and can be adjusted for
different observing modes and detector conditions.

**Chi-square assessment**

For exposures with sufficient degrees of freedom, the
goodness of fit is evaluated using the reduced chi-square:

.. math::

   \chi_{\nu}^{2} = \frac{\chi^{2}}{\nu},

where :math:`\nu` is the effective number of residual
degrees of freedom.

The routine evaluates the median reduced chi-square and
the fraction of assessed pixels exceeding a configurable
chi-square threshold.

These diagnostics can identify systematic deviations from
the assumed noise model or poor ramp-fitting performance.

For two-read correlated double sampling (CDS) exposures,
a conventional two-parameter linear fit has no residual
degrees of freedom. Consequently, reduced chi-square
cannot be meaningfully evaluated.

In this case, the chi-square assessment is marked as
not applicable:

.. code-block:: text

   RMPCHST = 'N/A'

The exposure is evaluated using the remaining applicable
quality criteria, including the valid-fit fraction.

For multi-read exposures, reduced chi-square is evaluated
where sufficient degrees of freedom are available. Its
interpretation depends on the number of valid differences
retained after saturation masking and jump rejection.

**Exposure-level quality flag**

The overall ramp-fitting quality is recorded in the FITS
header using the Boolean keyword ``RAMPGOOD``.

* ``RAMPGOOD = True`` indicates that the exposure satisfies
  all applicable ramp-fitting quality criteria.

* ``RAMPGOOD = False`` indicates that one or more applicable
  quality criteria have failed.

The quality flag provides an exposure-level assessment
rather than a guarantee that every detector pixel has
a valid fitted slope.

Individual failed pixels remain identifiable through
their fit-status values and detector quality flags.

**FITS header keywords**

The quality-assessment routine records the following
diagnostic quantities in the FITS header:

.. list-table:: Ramp-fitting quality assessment keywords
   :header-rows: 1
   :widths: 25 15 65

   * - Keyword
     - Type
     - Description

   * - ``RAMPGOOD``
     - Boolean
     - Overall ramp-fitting quality flag.

   * - ``RMPVFRAC``
     - Float
     - Fraction of successfully fitted assessed pixels.

   * - ``RMPFFRAC``
     - Float
     - Fraction of failed assessed pixels.

   * - ``RMPNFAIL``
     - Integer
     - Number of failed fits among assessed pixels,
       excluding master-BPM pixels by default.

   * - ``RMPCHI``
     - Float
     - Median reduced chi-square when applicable.

   * - ``RMPHCHI``
     - Float
     - Fraction of assessed pixels with reduced
       chi-square above the configured threshold.

   * - ``RMPCHST``
     - String
     - Chi-square assessment status
       (``N/A`` if insufficient degrees of freedom).

   * - ``RMPCLUST``
     - Integer
     - Size of the largest connected cluster of
       failed assessed pixels.

   * - ``RMPQCWHY``
     - String
     - Summary of the exposure-quality assessment.

Additional diagnostic statistics distinguish failed fits
among master-BPM pixels from failed fits among the
remaining detector pixels.

These metrics support automated exposure-quality
screening and monitoring of detector performance.

A successful exposure-level assessment does not imply
that every detector pixel is scientifically usable.
Pixel-level quality information must still be considered
during subsequent bad-pixel correction and spectral
extraction.


Output
^^^^^^

The ramp-fitting routine returns four two-dimensional
detector images:

* **Slope:** Fitted detector count rate in DN/s.
  Pixels with unsuccessful fits are assigned zero.

* **Pedestal:** Estimated detector signal offset
  associated with the fitted ramp. Failed fits
  are assigned zero.

* **Uncertainty:** Estimated uncertainty of the
  fitted count rate, incorporating the noise model
  used by the fitting method. Failed fits are
  assigned an uncertainty of ``1e30``.

* **Chi-square:** Goodness-of-fit statistic for the
  fitted detector ramp. Failed fits are identified
  using a value of ``-1``.

The saturation-masking stage additionally provides:

* ``quality_map``: Two-dimensional detector quality flags,
  identifying bad pixels, saturated pixels, pixels affected
  by neighboring saturation, and invalid saturation thresholds.

* ``good_read_mask``: Three-dimensional Boolean mask
  identifying the reads available for ramp fitting.

The ramp-fit quality assessment additionally provides:

* ``RAMPGOOD``: Boolean FITS header keyword indicating
  whether the exposure satisfies the configured
  ramp-fitting quality criteria.

* **Quality metrics:** Valid-fit fraction, failed-fit
  statistics, and applicable chi-square diagnostics.

* **FITS header diagnostics:** Quality-assessment
  statistics recorded in the output FITS header,
  including ``RMPVFRAC``, ``RMPFFRAC``, ``RMPNFAIL``,
  and ``RMPCHST``.

These products support subsequent detector calibration,
exposure-quality screening, bad-pixel correction,
and spectral extraction.

.. _bpmcorrect:

Bad Pixel Correction
--------------------

**Corrects detector bad pixels using a precomputed sparse
interpolation matrix.**

This primitive corrects pixels flagged in the master bad-pixel
mask generated by :ref:`createbpm`. The correction is performed
on the detector image after ramp fitting, replacing bad-pixel
values with estimates derived from neighboring valid pixels.

Rather than performing interpolation independently for every
exposure, the DRP constructs a sparse correction matrix using
inverse-distance weighted interpolation. The matrix is generated
from the detector bad-pixel mask and can be reused for subsequent
exposures with the same detector geometry and bad-pixel map.

This approach reduces the computational cost of bad-pixel
correction during routine data reduction.

Behaviour
^^^^^^^^^

* Identifies bad pixels using the supplied two-dimensional
  bad-pixel mask, where ``1`` indicates a bad pixel and
  ``0`` indicates a good pixel.

* Searches for neighboring good pixels within a square
  region centered on each bad pixel.

* Progressively expands the search region until at least
  the required number of good pixels is found.

* Uses inverse-distance weighting to reconstruct each bad
  pixel from the surrounding good pixels.

* Normalizes the interpolation weights so that their sum
  equals unity.

* Preserves the original values of all pixels not flagged
  in the bad-pixel mask.

* Leaves a bad pixel unchanged if the required number
  of good neighbors cannot be found within the maximum
  permitted search region.

* Stores the interpolation weights in a sparse matrix,
  allowing the correction to be applied efficiently
  through matrix multiplication.

* Supports regeneration of the correction matrix when
  an updated bad-pixel mask is provided.

Interpolation Method
^^^^^^^^^^^^^^^^^^^^

For each bad pixel, the routine searches for neighboring
good pixels within an expanding square region.

The search begins with a ``3 x 3`` pixel region and
increases in steps of two pixels until the minimum
number of good pixels is found or the maximum
search size is reached.

By default, the routine requires at least four
good pixels (``min_good_pixels=4``) within a
maximum search region of ``21 x 21`` pixels
(``max_box_size=21``).

The replacement value is calculated using
normalized inverse-distance weighting:

.. math::

   I_{\mathrm{corrected}}(x,y)
   =
   \frac{
   \sum_{j=1}^{N}
   w_j I_j
   }{
   \sum_{j=1}^{N} w_j
   },

where :math:`I_j` is the value of a neighboring
good pixel and :math:`w_j` is its interpolation
weight, defined as:

.. math::

   w_j = \frac{1}{d_j},

with :math:`d_j` representing the Euclidean
distance between the bad pixel and the
neighboring good pixel.

Closer pixels therefore contribute more strongly
to the reconstructed value.

Only pixels identified as good in the input
bad-pixel mask contribute to the interpolation.

If fewer than the required number of good
neighbors are found within the maximum
search region, the original pixel value
is preserved.

Sparse Correction Matrix
^^^^^^^^^^^^^^^^^^^^^^^^

The interpolation weights are stored in a
sparse matrix in compressed sparse row (CSR)
format.

For a detector image containing :math:`N`
pixels, the correction matrix has dimensions
:math:`N \times N`.

Each matrix row represents one output pixel:

* **Good pixels:** The corresponding matrix row
  contains a single diagonal element equal
  to one, preserving the original pixel value.

* **Bad pixels:** The matrix row contains the
  normalized interpolation weights associated
  with the selected neighboring good pixels.

* **Uncorrectable pixels:** If insufficient
  good neighbors are available, the matrix
  retains a diagonal element equal to one,
  leaving the original pixel value unchanged.

The correction is applied by flattening the
detector image into a one-dimensional array,
multiplying it by the sparse correction matrix,
and reshaping the result to the original
detector dimensions.

.. math::

   \mathbf{I}_{\mathrm{corrected}}
   =
   \mathbf{B}\,
   \mathbf{I}_{\mathrm{original}},

where :math:`\mathbf{B}` is the sparse
bad-pixel correction matrix.

The matrix can be saved in ``.npz`` format
and reused for multiple detector images
without recalculating the interpolation
weights.

Output
^^^^^^

The primitive returns a two-dimensional detector
image in which bad pixels have been replaced
by interpolated values whenever sufficient
valid neighboring pixels are available.

Pixels not flagged in the bad-pixel mask
retain their original values.

The corrected image preserves the dimensions
of the input detector image and is used
in subsequent detector calibration and
data reduction steps.

.. _spectralextract:

Spectral Extraction
-------------------

**Reconstructs calibrated detector images into three-dimensional
integral field spectroscopy (IFS) data cubes.**

After detector-level calibrations have been applied, the SCALES
DRP extracts spectra from the two-dimensional detector image
using the instrument rectification matrix generated during
calibration.

The extracted data cube contains two spatial dimensions
corresponding to the lenslet positions and one spectral
dimension corresponding to wavelength.

The dimensions of the output cube depend on the observing
mode, including the number of spatial lenslets and
wavelength bins.

.. figure:: /_static/plots/ifs_scales.png
   :width: 700px
   :align: center

   Illustration of the lenslet and slicer IFS formats,
   together with the hybrid lenslet-slicer (slenslit)
   concept used for the SCALES medium-resolution IFS.
   The slenslit combines lenslet-based spatial sampling
   with the longer spectra enabled by an image slicer.

The SCALES DRP provides two complementary spectral
extraction methods:

* :ref:`Optimal Extraction <optimalextract>` -- a fast,
  variance-weighted extraction based on the method
  described by Horne (1986).

* :ref:`Chi-square Extraction <leastextract>` -- a
  weighted linear least-squares extraction that fits
  the detector data using the instrument rectification
  matrix, independently for each lenslet.

Optimal extraction provides the initial spectral
flux estimates used to initialize the chi-square
extraction.

Both methods reconstruct the spectral flux
distribution in the form of a three-dimensional
IFS data cube.

.. _optimalextract:

Optimal Extraction
^^^^^^^^^^^^^^^^^^

**Extracts spectra using variance-weighted detector
profiles derived from monochromatic calibration data.**

The pipeline implements the optimal extraction
method described by
`Horne (1986)
<https://ui.adsabs.harvard.edu/abs/1986PASP...98..609H/abstract>`_.

The extraction uses the instrument rectification
matrix, which contains the detector profiles
associated with individual spectral channels
and spatial lenslets.

These profiles are determined from monochromatic
calibration point-spread functions (PSFlets)
obtained during the calibration process
(see :doc:`Calibration module <Mode_of_Pipelines>`).

For each spectral voxel, the extracted flux is
calculated as:

.. math::

   F_k =
   \frac{
   \displaystyle\sum_i
   P_{ki} d_i / \sigma_i^2
   }{
   \displaystyle\sum_i
   P_{ki}^2 / \sigma_i^2
   },

where:

* :math:`F_k` is the extracted flux for spectral
  voxel :math:`k`.

* :math:`P_{ki}` is the calibrated detector
  profile for voxel :math:`k` at detector
  pixel :math:`i`.

* :math:`d_i` is the measured detector
  pixel value.

* :math:`\sigma_i` is the detector-pixel
  uncertainty.

The corresponding formal uncertainty is:

.. math::

  \sigma_{F_k} =
  \left(
  \sum_i \frac{P_{ki}^2}{\sigma_i^2}
  \right)^{-1/2}.

The detector-pixel uncertainties are supplied
by the preceding detector processing and
ramp-fitting stages.

The extraction assumes independent detector-pixel
errors and uses the supplied uncertainty image
to construct the inverse-variance weights.

Behaviour
~~~~~~~~~

* Uses the rectification matrix generated from
  monochromatic calibration PSFlets.

* Converts the calibrated detector image and
  its uncertainty image into one-dimensional
  arrays for efficient matrix operations.

* Excludes detector pixels with non-finite
  signals, non-finite uncertainties, or
  non-positive uncertainties.

* Computes the variance-weighted flux
  independently for each spectral voxel.

* Propagates the input detector uncertainties
  to obtain a formal uncertainty for each
  extracted spectral voxel.

* Uses sparse matrix multiplication to
  efficiently evaluate the weighted sums.

* Assigns ``NaN`` to spectral voxels
  with insufficient valid profile weight.

* Provides the initial flux estimate
  used by the chi-square extraction.

Output
~~~~~~

The optimal extraction returns:

* A spectral flux vector that is reshaped
  into a three-dimensional IFS flux cube.

* A corresponding formal uncertainty
  vector that is reshaped into an
  uncertainty cube.

The cube dimensions are determined by
the observing mode and rectification matrix.

.. _leastextract:

Chi-square Extraction
^^^^^^^^^^^^^^^^^^^^^

**Extracts spectra using weighted linear least-squares
fitting of the detector image, independently for each
spatial lenslet.**

The chi-square extraction treats spectral extraction
as a linear inverse problem. The detector image is
represented as a combination of calibrated spectral
profiles contained in the rectification matrix.

The forward model is:

.. math::

  \mathbf{d} = \mathbf{R}\mathbf{A},

where:

* :math:`\mathbf{d}` is the observed detector
  image represented as a one-dimensional vector.

* :math:`\mathbf{R}` is the sparse rectification
  matrix describing how each spectral voxel
  contributes to the detector image.

* :math:`\mathbf{A}` is the unknown spectral
  flux vector.

The current implementation solves the inverse
problem independently for each spatial lenslet and
for each lenslet, the routine selects the columns
of the rectification matrix corresponding to its
wavelength channels and the detector pixels
illuminated by those profiles.

The extracted spectrum is obtained by minimizing:

.. math::

  \chi^2 =
  \sum_{i \in V}
  \frac{
  \left[
  d_i - (\mathbf{R}_{\ell}\mathbf{A}_{\ell})_i
  \right]^2
  }{
  \sigma_i^2
  },

where :math:`\mathbf{R}_{\ell}` is the
rectification matrix restricted to lenslet
:math:`\ell`, :math:`\mathbf{A}_{\ell}` is
its spectral flux vector, and :math:`V`
contains the valid detector pixels
associated with that lenslet.


Initial Flux Estimate
~~~~~~~~~~~~~~~~~~~~~

The chi-square extraction uses the spectral
flux estimated by :ref:`Optimal Extraction
<optimalextract>` as its initial solution.

The initial flux vector, ``A_guess``, is
reshaped into the three-dimensional cube
geometry and used to initialize the
least-squares solver for each lenslet.

The initial estimate can improve convergence
and reduce the number of iterations required
by the optimization.

The fit is not constrained to remain near
the initial estimate, and the initial
solution does not impose flux bounds.

Weighted Least-Squares Fitting
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

For each spatial lenslet, the routine
constructs a weighted system:

.. math::

  \mathbf{R}_{w}
  =
  \mathbf{W}\mathbf{R}_{\ell},

.. math::

  \mathbf{d}_{w}
  =
  \mathbf{W}\mathbf{d}_{\ell},

where :math:`\mathbf{W}` is a diagonal
weighting matrix with elements:

.. math::

  W_{ii} = \frac{1}{\sigma_i}.

The resulting least-squares problem is:

.. math::

  \min_{\mathbf{A}_{\ell}}
  \left\|
  \mathbf{R}_{w}\mathbf{A}_{\ell}
  -
  \mathbf{d}_{w}
  \right\|_2^2.

The optimization is performed using
``scipy.sparse.linalg.lsmr``, an iterative
least-squares solver designed for large,
sparse linear systems.

The solution is unbounded, allowing both
positive and negative fitted flux values.

Behaviour
~~~~~~~~~

* Uses the calibrated rectification matrix
  to model the detector response.

* Extracts each spatial lenslet independently
  using all wavelength channels associated
  with that lenslet.

* Selects the detector pixels contributing
  to the selected lenslet's spectral profiles.

* Excludes pixels with non-finite detector
  values, invalid variances, or flags in
  the optional bad-pixel mask.

* Uses the total input detector-pixel
  variance to construct the fitting weights.

* Initializes the solver using the flux
  estimate from optimal extraction.

* Solves the weighted least-squares problem
  using ``scipy.sparse.linalg.lsmr``.

* Does not impose non-negative flux
  constraints or upper flux bounds.

* Supports configurable solver tolerance
  and maximum iteration count.

* Records optional fitting diagnostics
  for individual lenslets.

* Assigns a configurable fill value
  to lenslets without usable detector
  pixels or when the fit fails.

Fitting Diagnostics
~~~~~~~~~~~~~~~~~~~

When diagnostic output is enabled, the
routine records the following information
for each spatial lenslet:

* ``chi2_per_dof`` -- reduced chi-square
  calculated from the weighted residuals.

* ``n_dof`` -- number of degrees of freedom,
  calculated as the number of selected
  detector pixels minus the number of
  fitted wavelength channels.

* ``istop`` -- termination status
  returned by the ``lsmr`` solver.

* ``n_iters`` -- number of solver iterations.

* ``failed`` -- Boolean indicator for
  lenslets where an exception occurred.

* ``fail_msg`` -- error description
  associated with a failed lenslet fit.

These diagnostics can be used to assess
extraction quality and identify lenslets
with unreliable or unsuccessful fits.

Output
~~~~~~

The chi-square extraction returns:

* A spectral flux vector that is reshaped
  into a three-dimensional IFS flux cube.

* Optional per-lenslet fitting diagnostics,
  including reduced chi-square, iteration
  counts, solver status, and failure flags.

.. _wcs:

World Coordinate System (WCS)
-----------------------------

**Constructs a three-dimensional World Coordinate System (WCS)
for the extracted IFS data cube.**

This primitive creates an ``astropy.wcs.WCS`` object that defines
the spatial and spectral coordinate systems of the extracted
integral field spectroscopy (IFS) data cube.

The WCS maps the two spatial axes to right ascension (RA) and
declination (Dec) using a tangent-plane (TAN) projection, while
the third axis represents wavelength.

The coordinate system is constructed using information from
the input FITS header, the observing mode, and the appropriate
spatial reference pixel. The routine accounts for variations
in FITS header conventions, including different representations
of sky coordinates and optional header keywords.

The resulting WCS provides the coordinate transformations
required to associate individual cube elements with their
corresponding sky positions and wavelengths.

Behaviour
^^^^^^^^^

* Reads the reference sky coordinates (RA and Dec) from the
  input FITS header, supporting different coordinate formats.

* Determines the spectral coordinate system from the wavelength
  solution associated with the observing mode and filter
  configuration.

* Applies the spatial pixel scale and position angle to define
  the orientation and sampling of the extracted IFS cube.

* Selects the appropriate spatial reference pixel based on the
  observing mode and filter configuration, falling back to a
  default reference pixel when necessary.

* Uses a tangent-plane (TAN) projection to describe the
  spatial coordinates in RA and Dec.

* Defines the wavelength axis as the third coordinate axis
  of the three-dimensional WCS.

* Handles missing or optional FITS header keywords by
  applying default values where supported.

* Constructs an ``astropy.wcs.WCS`` object that enables
  transformations between IFS cube pixel coordinates and
  world coordinates.

Output
^^^^^^

Returns a three-dimensional ``astropy.wcs.WCS`` object
describing the spatial and spectral coordinate systems
of the extracted IFS data cube.

The WCS provides the mapping between cube pixel
coordinates and their corresponding RA, Dec, and
wavelength values.
